Git en entreprise :

Quand j'arrive en entreprise :
[  ] Générer les clés ssh (pv et pb) (avec la méthode git)
[  ] Donner la clé ssh pb a github
[  ] Git clone via ssh (attention : ici on récupère seulement la branch main du repo)
[  ] Importer l'environnement virtuel (voir tuto env dans le chapitre suivant)

Tous les jours :

[  ] activer l’env virtuelle : nom_env/Scripts/Activate
[  ] En local, S'assurer d'être sur la branche main/develop
[  ] Git pull de la branch main/develop
[  ] Git branch (Créer une new branch perso)
[  ] Aller sur la branch creer (Git checkout)
[  ] Faire les modifications de code + reformater le code avec le package Black
[  ] Ajouter les modifs à l'index (Git add)
[  ] Git commit à chaque fin de journée
[  ] Git push de la branch perso sur le repo distant
[  ] Creer un Pull request (from branch perso to main/develop)
[  ] Dde au manager de regarder mon pull request ( envoyé le lien de la conv pull request par teams)
[  ] Le manager approuve le code (click bouton sur github), Pull request accepté
[  ] Le chef de projet ou moi faisons : le Merge pull request
[  ] Supprimer la branch sur github et en local
[  ] Les 2 collaborateurs font un Git pull de la branch main en local, pour être sur la même longueur d'onde

A retenir (pour éviter les conflits): lorsque 2 ind travaillent sur un même projet, ils doivent tous les 2 Créer leur propre branche et ne pas modifier le même fichier en même temps.

[  ] Aller sur la branch creer  : Git checkout nom_branch
[  ] Faire les modifications de code + reformater le code avec le package Black

    Félicitations pour votre nouveau PC ! Pour pousser du code sur votre dépôt GitHub existant, suivez ces étapes générales :
    
    1. **Installer Git :**
    Assurez-vous d'avoir Git installé sur votre nouveau PC. Si ce n'est pas le cas, vous pouvez le télécharger depuis [le site officiel de Git](https://git-scm.com/).
    2. **Cloner votre dépôt existant :**
    Utilisez la commande suivante dans votre terminal pour cloner votre dépôt GitHub sur votre nouveau PC. Remplacez **`URL_DU_REPO`** par l'URL de votre dépôt GitHub.
        
        ```bash
        bashCopy code
        git clone URL_DU_REPO
        
        ```
        
    3. **Changer de répertoire :**
    Accédez au répertoire cloné en utilisant la commande **`cd`**.
        
        ```bash
        bashCopy code
        cd NOM_DU_REPO
        
        ```
        
    4. **Configurer Git :**
    Configurez votre nom d'utilisateur et votre adresse e-mail si ce n'est pas déjà fait.
        
        ```bash
        bashCopy code
        git config --global user.name "VotreNom"
        git config --global user.email "votre@email.com"
        
        ```
        
    5. **Ajouter et pousser les modifications :**
    Faites vos modifications dans le code, puis ajoutez et commitez les changements.
        
        ```bash
        bashCopy code
        git add .
        git commit -m "Description du changement"
        
        ```
        
    6. **Pousser vers GitHub :**
    Enfin, poussez vos modifications sur GitHub.
        
        ```bash
        bashCopy code
        git push origin NOM_DE_VOTRE_BRANCHE
        
        ```
        
        Assurez-vous de remplacer **`NOM_DE_VOTRE_BRANCHE`** par le nom de la branche sur laquelle vous travaillez (par exemple, "main" ou "master").
        
    
    Ces étapes devraient vous permettre de pousser vos modifications sur votre dépôt GitHub depuis votre nouveau PC. Assurez-vous également d'avoir les droits d'accès nécessaires pour effectuer ces opérations sur votre dépôt.

- Branches git : Gestion de conflits (Quand 2 personnes modifient le même fichier)
    
    Gestion de conflit avec github : 
    
    - Tout est indiqué sur github
    
    Gestion de conflit avec git rebase (en local) :
    
    - 1/ à ce moment là, la collegue a deja tout pushé et mergé sur la branch main (puis elle se casse). Tout est bon pour elle. Il n’y a que moi qui n’ai pas pushé/mergé.
    - 2/ Je fais le add, commit. Puis, Je push ma branche perso sur le repo github.
    - 3/ je créer une pull request (PR) (branch perso to main),  et on voit qu’il y a un conflit (il faut donc régler ça avant).
    - 4/ à partir de ce moment là, on va sur la branch main en local : git checkout main
    - 4*/ on importe le codes le plus récent : git pull
    - 5/ puis on revient sur notre branch perso : git checkout branch_perso
    - 6/ on fait un rebase sur la branch_main à partir de la branch_perso (pour remettre les commit de la branch main au debut et mettre à la suite le commit de la creation de la branch) : “git rebase main”
    - 7/ on résoud le conflit : en modifiant le fichier concerné par le conflit + reformater le code avec le package Black
    - 8/ on ajoute à l’index : git add script_conflit.py
    - 9/ git rebase - -continue
        - 9*/ Il y aura un script ouvert par VIM, on fait : échap, puis “:wq”
        - 9*/ ou un script ouvert par NANO, on fait : crlt +X
    - 10/ Vérifié que le script fonctionne bien
    - 11/ on push notre branch perso : git push -f
    - 12/ Pull request + Merge : branch perso sur la main
    - 13/ Supprimer les branch perso inutiles sur github et en local
    - 14/ Le lendemain, les 2 collègues màj la branch main/develop en local : git pull
    
    Attention : si on a une branch dev, et bien on doit faire la même chose en remplaçant main par develop
